**记录日期：** 2026-11-11
**研究主题：** 将 Cursor Projects 宣传中的 Agent-to-Agent 协作思想转化为跨厂商、可授权接入的开放基础设施。

## 我们要抽象的机制

1. **Agent 身份与发现：** 能力描述、Agent Card、接口版本、可信认证。
2. **任务委派与状态交接：** 创建、等待、处理、完成、失败、取消、结果回传。
3. **Agent 间协调：** 依赖管理、任务归属、冲突预防、协商与审计。
4. **项目共享记忆：** 项目事实/决策可版本化，私人上下文隔离，变更有证据。
5. **持续工作：** 断点续接、崩溃恢复、重试租约与成本控制。
6. **多团队治理：** 审批、权限边界、多租户、跨组织共享策略。

## 与现有标准的关系

- A2A 解决 Agent 间消息与任务交换，不自动解决身份可信、计划正确性或质量。
- MCP 是 Agent 使用工具/数据的通道；不应与 A2A 互相替代。
- Agent Skills 提供可移植的调用流程说明，但并不能自动为封闭产品授予网络或工具权限。
- Mesh 作为中立协调层，在两套协议之外提供审计、共享记忆、授权和业务策略。

## v0.1 的实现边界

已实现基础 HTTP/A2A 子集、Python Agent、SQLite 任务及事件记录、授权范围、简单委派限制、版本化知识库、Skill 和示例客户端；仍需第三方 SDK 一致性测试。

未实现：完整 A2A 1.0、可靠流式会话、生产级分布式调度、企业身份、全面审批、租户隔离、完整 MCP 服务端及自主协调器。

## 待验证的问题

- 跨不同 Agent SDK 的成功率、语义兼容和错误处理
- 长任务在网络中断或部署切换后能否安全恢复
- 多 Agent 场景下的返工率、成本、延迟和质量
- Shared Memory 的错误传播、并发冲突与信息泄漏
- 不同行业的合规、隐私和商业化需求

**优先级：** 先可互操作、安全、可复现；再扩大 Agent 数量与自治能力。
